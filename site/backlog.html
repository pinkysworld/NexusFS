Backlog

Prioritized by what unlocks the next milestone.

The backlog is grouped by execution order, not just by subsystem. With the local core, the S3 facade, verified replication, encryption and energy-aware scheduling all in place, the focus moves to operational hardening and closing the gaps those milestones opened.

Now

Close the energy follow-ups: on-demand fetch of deferred content, and metered-link detection.

Next

Incremental snapshots, batched storage writes, and collecting orphaned inode records.

Later

The POSIX facade, per-recipient key envelopes, and push notification of new operations.

Research

Keep ZK, privacy, and advanced systems work feature-gated until the baseline is solid.

Highest-priority backlog

  • Fetch deferred content on demand, so a power-constrained node can still serve a file when asked
  • Detect metered links per platform, so that scheduler rule can fire in the field
  • Push notification of new operations, so peers do not wait for the poll interval
  • Per-recipient key envelopes, so replicas need not share one repository key

Next unlocks

  • Batch storage writes — sled currently fsyncs on every chunk
  • Rebuild snapshots incrementally rather than walking the whole path
  • Prioritise which deferred content to fetch first under a capped budget
  • Implement the POSIX/FUSE facade

Planning

Roadmap and backlog now work together

The roadmap defines milestone outcomes. The backlog defines the concrete queue that moves the project toward those outcomes.
